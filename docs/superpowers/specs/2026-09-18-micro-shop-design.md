# 微型商城设计文档（VODAR）

> 范围：在 Cloudflare Pages 免费范围内，自建一个微型商城。海外信用卡收款（连连收单，先模拟支付跑通）、订单合并购买、买家凭订单号查物流与售后、商家后台带密码管理。
>
> 状态：设计定稿，待实现。

---

## 1. 需求定稿

在 Cloudflare Pages 免费范围内自建一个微型商城：

- 卖 **1 个手环套装 + 1~2 个配件**，目标是海外客户
- 支持海外信用卡收款（**连连全球收单**，先用模拟支付跑通，拿到正式凭据后无缝切换）
- 订单支持**一单合并选购**（一次付款买"本体 + 配件"一套，也可单独买配件）
- 买家**免登录**，凭订单号查询订单状态与物流
- 售后（退货/换货等）通过工单流程，**退款永久人工**
- 付款成功**自动发邮件**（含订单号，用 Cloudflare 免费额度）
- 商家用一个**带密码的后台**录入物流、看订单、处理售后

## 2. 整体架构

```
[买家端]                    [Cloudflare Pages]                    [商家端]
商品页下单 ──▶ Pages Functions ──▶ 生成订单/存 D1 ──▶ 商家后台(带密码)
付款(连连/模拟) ──▶ 支付回调 ──▶ 订单状态更新            ├─ 看新订单、填物流
订单查询(输单号) ──▶ 显示物流+售后 ──▶ 售后工单          └─ 看售后、填处理、改状态
售后提交 ──▶ 记录
付款成功 → 自动发邮件(免费额度)
```

- **页面**：沿用现有 Cloudflare Pages（`index.html` + `logo.png`），扩展出商品下单页、订单查询页、商家后台页
- **后端**：**Pages Functions**（含在 Pages 免费范围内）处理下单、查询、后台、邮件
- **数据库**：**Cloudflare D1**（免费数据库）存订单、订单项、物流、售后、商品、配置
- **邮件**：**Resend 免费档**（3000 封/月、100 封/天）给买家发含订单号的通知邮件；`vodar.net` 需在 Resend 完成域名验证（SPF/DKIM DNS 记录）以避免进垃圾箱
- **语言/风格**：全程英文界面，沿用 VODAR 品牌红 + 现有视觉风格

## 3. 商品与订单模型

### 商品（配置化，非写死）

| SKU | 商品 | 类型 | 示例定价 |
|:--|:--|:--|:--|
| P1 | VODAR 手环套装（含主体+标配配件） | 主商品 | $100 |
| P2 | VODAR 充电线（单卖） | 配件 | $15 |
| P3 | VODAR 备用表带（单卖） | 配件 | $20 |

商品存于 **products 表**（含价格与"可售/下架"开关）：价格可随时改；**配件断货时后台一键下架**，买家端立即不可下单（不做库存数量管理）。

### 订单（一单可含多行）

```
一笔订单(Order)
 ├─ 订单号：唯一，如 VOD-26A1B2（买家凭它查）
 ├─ 买家信息：姓名 / 邮箱 / 收货地址（下单时一次填完）
 ├─ 商品行(LineItems)：可多行
 │    ├─ 手环套装 x1  $100
 │    ├─ 充电线  x1  $15
 │    └─ 备用表带 x1  $20   ← 可同时选
 ├─ 金额：合计
 ├─ 状态：待支付 → 已支付 → 已发货 → 已完成
 └─ 关联：物流、售后工单(可多个)
```

订单状态：`待支付 → 已支付 → 已发货 → 已完成`；物流信息挂在"已发货"状态。

## 4. 买家端页面与下单流程

| 页面 | 功能 |
|:--|:--|
| 首页（商品展示） | 展示 P1~P3 商品卡（名称/图/价），"加入订单"；已下架商品不显示或标"Out of Stock" |
| 下单页 | 勾选数量，填姓名/邮箱/收货地址，确认金额后提交（**提交按钮点击后立即禁用，防重复下单**） |
| 付款确认页 | 付款成功页，**直接显示订单号** |
| 订单查询页 | 输入订单号 → 显示状态、商品、物流跟踪号、售后入口（只读脱敏） |
| 售后提交 | 挂在查询页内，买家填类型+描述+联系方式并提交（需邮箱二次校验） |
| **隐私政策页** `/privacy.html` | GDPR 合规：收集哪些个人信息、用途、存储与删除权 |
| **退货政策页** `/returns.html` | 欧盟 14 天无理由退货权说明、退货流程与联系方式 |

### 买家下单流程
```
浏览商品 → 勾选要买的一套/配件 → 填收货信息 → 确认金额 → 模拟/连连付款
   → 付款成功 → 页面显示订单号 + 自动发邮件(含订单号) → 完
```

### 售后流转
```
买家提交售后工单（类型+描述+联系方式）
   → 商家后台「售后处理」列表（待处理）
   → 商家查看/联系/决定处理方式 → 填处理结果回工单
   → 标记处理中/已解决（买家查询页可见进度）
```

## 5. 商家后台与安全

### 商家后台板块
| 板块 | 功能 |
|:--|:--|
| 订单管理 | 看新订单（时间/商品/金额/买家）、点开看收货信息 |
| 发货/物流录入 | 对"已支付"订单录入承运商 + 国际跟踪号，状态→已发货 |
| 售后处理 | 看买家售后工单（订单号/问题），填处理方式、改状态 |
| 商品开关 | 一键"可售/下架"任一商品（含改价格） |
| （预留升级位） | "通知开关"字段，未来可切邮件提醒 |

### 访问与安全（保持简单但护住数据）
- **登录**：后台密码，存 Cloudflare 环境变量（Secrets），不写进源码
- **后台登录限速（终审新增，需求 #15）**：登录失败节流（如连续失败 5 次锁定 15 分钟，按 IP 记忆于 KV/D1），不适用"不做频控"豁免，防暴力破解
- **接口校验**：每个后台接口校验登录态，防直接调 API 改订单
- **支付回调验签（终审新增，需求 #14）**：切换连连真实收单后，回调必须按连连提供的签名算法验签；**验签失败的"支付成功"一律拒绝**，防止伪造回调白拿货
- **下单幂等（终审新增，需求 #18）**：后端对"同邮箱 + 同商品组合"在 60 秒内的重复提交只生成一笔订单
- **订单查询安全（关键加固，对应需求 #13）**：
  1. **查询只读 + 脱敏**：输订单号只查看物流/状态，不显示收货地址、完整邮箱等敏感信息
  2. **售后二次校验**：发起售后时，除订单号外还需校验下单邮箱（显示中间位如 `j***@gmail.com`，匹配才放行），让"单纯拿到单号"无法发起售后
  3. **退款永久人工**：系统只提交工单，**永不自动退款**；由商家后台审慎核实后人工执行
- **明确不做**：完整用户系统、多角色、审计日志、面向公众接口的频率限制（YAGNI；**后台登录限速是唯一例外**）

## 6. 数据模型（D1 数据库）

```
表 products（商品）
 ├─ id            主键（P1/P2/P3）
 ├─ name          商品名
 ├─ price_amt     单价(分)
 ├─ active        可售/下架开关（终审新增，需求 #19）
 └─ image         商品图路径

表 orders（订单）
 ├─ order_id        文字主键，唯一（如 VOD-26A1B2，含随机后缀防枚举）
 ├─ customer_name / email / address / city / country / zip
 ├─ status          待支付→已支付→已发货→已完成
 ├─ total_amt       订单总金额(分)
 ├─ payment_status  支付状态（模拟/真实共用）
 └─ created_at      下单时间

表 order_items（订单商品行，一对多）
 ├─ order_id      外键→orders
 ├─ product_id    对应商品
 ├─ qty           数量
 └─ unit_price    单价(分)

表 tracking（物流，一订单可多条）
 ├─ order_id      外键
 ├─ carrier       承运商(EMS/DHL等)
 ├─ tracking_no   国际跟踪号
 ├─ status        物流状态
 └─ updated_at

表 after_sales（售后工单）
 ├─ id            自增
 ├─ order_id      外键
 ├─ type          退货/换货/其他
 ├─ subject       标题
 ├─ detail        描述
 ├─ contact       买家联系方式
 ├─ status        待处理→处理中→已解决
 ├─ resolution    商家处理说明
 └─ created_at

表 settings（配置）  ← 预留
 └─ 通知开关、商品定价等可改项
```
